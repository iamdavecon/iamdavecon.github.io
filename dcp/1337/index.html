Legacy Compatibility Standard

1. Abstract

This document defines compatibility with legacy hacker terminology, obsolete communications protocols, ancient memes, and systems that everyone insists are still perfectly usable.

2. Compatibility Classes

Implementations MAY support ARCHAIC, DEPRECATED, STILL RUNNING, and NOBODY KNOWS WHO OWNS IT classes.

3. Translation

Legacy terms SHOULD be preserved when they provide useful shared context. They MUST NOT be used to exclude participants who have not encountered the relevant decade.

4. Migration

New systems SHOULD document replacement terminology and provide a migration path. A migration path that consists only of “you should know this already” is non-conforming.

5. Security Considerations

Obsolete protocols MAY contain obsolete vulnerabilities. Nostalgia is not a patch. Legacy systems MUST NOT be exposed merely to demonstrate that they still boot.
