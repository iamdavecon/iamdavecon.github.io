Purpose and Scope

DaveCon Standards & Protocols (DCPs) define recommended practices, technical standards, operational procedures, and other matters requiring considerably more documentation than judgment would suggest.

Terminology notice. The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY, and OPTIONAL in these documents are to be interpreted as though someone at DaveCon had the authority to enforce them.

02 / GOVERNANCE

The DCP Process

A standard becomes official through a lifecycle designed to ensure that no simple problem remains simple for long.

Questionable idea
↓
Unnecessary documentation
↓
Draft DCP
↓
Argument
↓
More documentation
↓
Accepted
↓
Immediately ignored

DCP numbers are assigned by an unspecified Dave authority and are generally permanent, except when they aren’t. Rough consensus and running code are encouraged. Neither has historically been required.

03 / CONTRIBUTIONS

Submit a DCP

There is no backend submission system at this time. This is a feature of the current security model.

Proposed documents SHOULD include:

  • title and abstract
  • motivation and specification
  • security considerations
  • Durch considerations, where applicable
  • references
  • evidence that writing the DCP was preferable to simply solving the problem
